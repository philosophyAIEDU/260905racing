## 확인한 자동 테스트

15개 테스트가 실제로 통과했다. game-core와 schema로 제한한 커버리지 측정에서 문장·분기·함수·라인 100%를 확인했다. 이것은 전체 앱 커버리지 100%를 뜻하지 않는다.

- 조향 보조, 데드존, 그립 곡선, 추진력 상한, 시간 표기
- 닫힌 코스, 정방향 체크포인트 판정, 역주행·체크포인트 생략 방지
- 3바퀴 완주, 무제한 연습, 복귀 페널티
- 차량 JSON과 설정/기록 검증
- 실제 Rapier 엔진의 접지, 가속, 제동, 후진, 우회전, 뒷바퀴 드리프트 그립

점검 브라우저에서 초기 메뉴 DOM은 확인했다. 이후 WebGL 비활성화 오류를 확인하여 미지원 안내를 추가했다. 추가 브라우저 확인은 자동 승인 검토가 사용량 한도로 거절했다. 이를 우회하지 않았으며 브라우저 통합 테스트 성공으로 기록하지 않는다. 저장소에 포함한 Playwright 테스트는 실행 환경을 갖춘 곳이나 GitHub Actions에서 별도 결과를 확인해야 한다.

## 구조와 성능상의 결정

- 물리는 60Hz 고정 tick, 렌더는 R3F, Rapier interpolation 사용. 차량 수치와 랩 상태는 mutable 객체에서 갱신하고 HUD는 10Hz로 DOM만 갱신한다. `useFrame`에서 React `setState`를 호출하지 않는다.
- 아케이드 조작을 위해 낮은 무게중심, 보정 관성, 속도 연동 조향과 낮춘 제동력을 선택했다. 서스펜션 자체는 독립 raycast 방식이다.
- 코스·자동차는 외부 자산이 필요 없는 절차적 지오메트리다. 원본 텍스처나 라이선스 불명 모델을 내려받지 않는다.
- 기본 렌더러는 WebGL2다. WebGPU/TSL, HDRI, CSM, 후처리, 날씨, LOD 3단계와 자동 벤치마크는 Phase 2 범위다.
- 휠 상태를 읽는 Rapier JS 바인딩과 브라우저 Gamepad API의 반환 객체까지 포함한 힙 할당 0은 검증하지 않았다. 애플리케이션 카메라 벡터는 재사용한다.
- 출시용 JS gzip은 빌드 기준 약 1.1MB다. 초기 로딩 8초나 실제 프레임 예산은 네트워크/기기 조건에 따라 별도 측정해야 한다.
- 이 작업 환경의 Node 24에서 타입/테스트/빌드를 확인했다. 저장소 `.nvmrc`와 CI는 명세대로 Node 22를 지정한다.

## 새 환경변수와 다음 단계 결정

현재 필요한 환경변수는 **없다**. API 키를 프런트엔드에 입력하거나 넣는 곳도 없다. `.env.example`은 이 사실을 설명하기 위해 제공했다.

Phase 2에 들어가기 전에 대상 데스크톱/모바일 최소 사양과 사용할 정식 차량·환경 자산을 결정하고 해당 기기로 성능·조작감을 평가해야 한다. Phase 4 전에는 실제 사용 가능한 모델 ID, 음성 제공자, 호출 예산을 정해야 한다. 유료 서비스나 새 계정은 이번에 만들지 않았다.
